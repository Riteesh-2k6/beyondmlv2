## Rulings

One line each: what was decided, why, what it costs if wrong.

1. **The session runs on the gateway's loop in a daemon thread; the TUI is an in-process client.** The harness makes sync git and subprocess calls that would stutter a Textual loop. If wrong: an extra `run_coroutine_threadsafe` hop per TUI command, trivially removable.
2. **`run_goal` gains `bus=`.** Otherwise the gateway would have two buses writing the same files. If wrong: a one-line merge conflict with `harness/core`.
3. **Prompts are ids on the existing kinds, resolved by a second event with `answer`.** Keeps `KINDS` fixed and makes pending prompts replay-derivable for reconnects. If wrong: clients fold one extra rule.
4. **Prompt events are authored by the asking agent; questions use the agent of the last id-less `question` event (tracked by a bus subclass).** The asker callback has no agent argument and the core signature stays. If wrong: a question could be attributed to the wrong agent when two agents ask in the same instant; the modal still works.
5. **The user's chat lines are `message_delta` events by agent `user`.** The transcript then replays on reconnect. Cost if wrong: an `agents/user/` folder in the project.
6. **The lead is rebuilt per chat turn.** Its instruction embeds PLAN.md, which changes during a run. Cost: one cheap object per message.
7. **No ADK `get_fast_api_app`.** It brings ADK's session routes and conventions for nothing we show. Cost if wrong: a later mount of ADK's app alongside ours.
8. **SSE over `StreamingResponse`, no `sse-starlette`.** Thirty lines of stdlib-level code beat a dependency. Cost: we own the heartbeat.
9. **Starting a run is `POST /projects/{p}/run`, not an `/input` type.** Different lifecycle (409 while running). Cost: one extra route beyond the spec's list.
10. **Project registry is in memory, seeded by the CLI's project.** A persistent list is a feature nobody asked for yet. Cost: projects created from the web are forgotten on restart (they stay on disk).
11. **Upload goes to `data/raw/<name>` via `POST /projects/{p}/upload`.** A browser cannot hand over a filesystem path. Cost: one route.
12. **The dependency graph is drawn as topological layers.** Arbitrary edge routing in a terminal is not worth it; the web draws real edges between layered nodes. Cost: a wide DAG wraps.
13. **Gateway serves the built UI with an `index.html` fallback; API routes stay at the root per spec.** Client routes live under `/p/...` and never collide with `/projects`. Cost: a catch-all route.
14. **The TUI uses one Screen with a `ContentSwitcher` plus a modal, not a Screen stack.** The chat dock must be on every screen. Cost: none visible.
15. **`beyondml` outside a project exits 2 with the init hint.** Creating a git repo in an arbitrary cwd is surprising. Cost: one extra command for first-timers.
16. **`beyondml tui` becomes an alias of the new TUI; `beyondml web` is removed.** `serve` replaces it. Cost: a changed habit.
17. **No JS test runner.** tsc strict plus `vite build` plus a browser round against a real gateway is the web's verification; adding vitest is a new dependency for sub-project-4-only tests. Cost: reducer logic is checked by the browser pass only.
18. **Plotly comes from the `plotly-basic` dist already inside `plotly.js`**, lazy-loaded into its own chunk; no new npm dependency, 1.2 MB only when a chart renders. Cost: no 3D/geo chart kinds, which we do not emit.
19. **No run-lifecycle event kind.** The web refetches `GET /projects/{p}` (debounced) on step_status, prompt, error and plan_updated events; the TUI reads `session.running` in-process. Keeps `KINDS` fixed. Cost: a few hundred ms of staleness on the "running" indicator.
20. **Geist and Geist Mono stay** despite the detector's overused-font warning: PRODUCT.md's terminal-native tone and the incumbent tokens pin them, and Operate surfaces are served by workhorse faces. Cost: a less distinctive display voice, which this console does not want.
21. **`web/ui/dist` is not committed.** The gateway serves it when present; `npm run build` produces it. Cost: a pip install without Node has no web UI (the TUI and API still work).
22. **No concept roll for the web.** The six screens are fixed by the spec and the visual world is pinned, so new-work's "precisely specified request" path applied: inherit, build, review. Cost: none intended; recorded so the skipped roll is not mistaken for an oversight.
23. **The impeccable finish review and documenter ran as fresh general-purpose subagents** from the skill's degraded references (the shipped agent definitions are not installed here). Read-only, so the owner's "no implementer subagents" rule holds. Cost: none.

### Task 2: Session
**Files:** `beyondml/gateway/__init__.py`, `beyondml/gateway/session.py`, `beyondml/gateway/state.py`; modify `beyondml/harness/run.py` (`bus=`). **Test:** `tests/test_session.py`.

```python
class SessionBus(EventBus):           # remembers the agent of the last id-less question
class Session:
    def __init__(self, root: Path, *, mode=None, model=None, resolver=None, create_goal=None)
    project, bus, pending: dict[str, dict], run_task
    def bind(self) -> None            # record the running loop
    async def start(self, goal, data=(), *, mode=None, model=None) -> None   # RuntimeError if running
    def stop(self) -> bool
    @property running
    async def answer(self, id, answer) -> None     # KeyError for unknown id; emits the resolved event
    async def chat(self, text) -> str
    def summary(self) -> dict          # name, root, goal, mode, model, running, pending
    async def call(self, coro)         # run on the session loop from any loop
def fold(events) -> SessionState      # steps {id: {status, started, finished, reason}}, pending {id: data},
                                      # chat [...], generations {agent: [...]}, trials, charts {agent: [...]}, artifacts {agent: [paths]}
def plan_view(project, state) -> dict  # plan.json + per-step started/finished/metric/elapsed
```

Tests: a scripted run whose step calls `ask_user` parks on `pending`, `answer()` resolves it and the run finishes; approver kind `plan` in mode auto parks and resolves; `fold` of a replay yields pending ids and resolved ones; `chat` emits a `user` delta and returns the lead's text; `start` while running raises.
